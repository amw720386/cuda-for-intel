# ZLUDA parity: measured gaps and roadmap

This page compares cuda-for-intel (branch `hw-validate`, 108d59a) with ZLUDA (github.com/vosen/ZLUDA, HEAD f4df215, 2026-11-03). It is research only: no GPU was used and no existing code was changed.

Scope follows the owner's choices: API coverage, PyTorch and frameworks, translator hardening, packaging, performance, and community and hygiene. Linux is out of scope. Testing breadth appears only where it supports another area.

How to read the evidence:
- **Measured**: a count produced by a script in this branch, or a fact read from the source. ZLUDA paths are relative to a ZLUDA checkout.
- **Estimate**: an impact or effort judgement.
- **Stated by ZLUDA**: a claim from ZLUDA's docs or blog that was not reproduced here.

## 0. How the numbers were produced

```
git clone --depth 1 https://github.com/vosen/ZLUDA <zluda>
python3 -I scripts/zluda_parity/parity.py <zluda> . <outdir>               # library table, writes <outdir>/parity.json
python3 -I scripts/zluda_parity/parity.py <zluda> . <outdir> --torch-gaps  # adds torch_cuda imports neither side implements
python3 -I scripts/zluda_parity/parity.py <zluda> . <outdir> --write-doc   # rewrites the section 1 table below (--check-doc: CI gate)
python3 -I scripts/zluda_parity/ptx_ops.py <zluda> .                       # PTX opcode table
```

ZLUDA side:
- "Declared" counts the `fn` items in `cuda_macros/src/<lib>.rs`. That file is the bindgen output for the NVIDIA header.
- "Implemented" counts the names in the non-default `<= [...]` lists of each crate's `cuda_macros::*_function_declarations!` call: `zluda/src/lib.rs`, `zluda_blas`, `zluda_blaslt`, `zluda_dnn`, `zluda_fft`, `zluda_sparse` and `zluda_ml`.
- Every other declared name is exported and returns `unimplemented()`.

Our side:
- The script reuses `scan()` from `scripts/api_audit.py`. An exported function whose body is a single constant or error expression counts as a stub.
- A symbol defined only in a `stubs.rs` file also counts as a stub.

Caveats (measured):
- The two "implemented" numbers are not the same test. ZLUDA's lists are hand-curated forwards to HIP/rocBLAS/MIOpen. Ours come from a body heuristic, so a function that returns success without real work counts as implemented. Conversely, a correct constant getter such as `cudnnGetVersion` counts as a stub.
- `docs/api-coverage.md` was stale at 108d59a (`api_audit.py --check` exited 1). It has been regenerated, and CI now runs `api_audit.py --check` and `parity.py --check-doc` against ZLUDA pinned at f4df215 (roadmap item 18).

### What ZLUDA implements that we do not (measured, `parity.json`)

**Driver API (36).** These fall into four groups:
- Texture references only (`cuTexRefSet*` x6, `cuModuleGetTexRef`, `cuModuleGetSurfRef`, `cuSurfRefSetArray`). Texture and surface objects and CUDA arrays are implemented since items 16 and 17 (`docs/textures.md`).
- D3D11 interop (`cuD3D11GetDevice`, `cuGraphics*` x6). Our audit excludes these on purpose.
- Small items: `cuCtxCreate_v4`, `cuMemHostGetDevicePointer_v2`, `cuMemRetainAllocationHandle`, `cuProfilerStart/Stop`, the unversioned `cuCtxPushCurrent`/`cuCtxPopCurrent`/`cuDeviceTotalMem`, and two `_ptds` aliases.

Texture support is what ZLUDA's Q1/Q2 2026 post credits for Blender working.

**cuFFT (0).** ZLUDA's 32 (plan creation 1d/2d/3d/many/many64, size estimates, `Exec{C2C,R2C,C2R,Z2Z,D2Z,Z2D}`, `SetStream`, `SetWorkArea`, `SetAutoAllocation`, through hipFFT) are all implemented since item 9. We also implement `cufftXtMakePlanMany`, `cufftXtExec`, `cufftXtGetSizeMany` and the three plan-property calls.

**cuSPARSE (0).** ZLUDA's 16 (`cusparseCreate`/`Destroy`, dense and COO descriptors, the legacy descriptor getters, and `cusparseSpMM` with bufferSize and preprocess, through rocSPARSE) are all implemented since the cuSPARSE shim. We also implement CSR/CSC descriptors, `cusparseSpMV`, `cusparseSDDMM`, `cusparse{S,D}bsr{mv,mm}`, `cusparseXcoo2csr`/`Xcsr2coo`, `cusparseCreateIdentityPermutation`, strided batches and pointer mode (81 in all; f32 and f64 only).

**cuBLAS (1)**, **cuBLASLt (5)** and **cuDNN (3)**: version, status-string and vector-copy helpers only. These are trivial. The cuBLAS one is `cublasGetCudartVersion`, which we implement as a constant and the audit therefore counts as a stub.

### What we implement that ZLUDA does not (measured)

- **Driver API: 109 entry points.**
  - The explicit graph API: 51 `cuGraph*`, including node add, get and set, exec update and clone. ZLUDA has 7 graph calls that forward to hipGraph.
  - Memory pools and VMM: `cuMemPool*`, `cuMemCreate`, `cuMemAddressReserve`, `cuMemAllocAsync`, prefetch and advise.
  - IPC (5), peer copies, `cuLaunchCooperativeKernel`, `cuLaunchHostFunc`, stream callbacks, and stream getters.
- **cuDNN: 94 against 40.** These include the backend (graph) API and an explicit-GEMM conv that runs on our XMX cuBLAS. See `docs/cudnn-shim.md`.
- **NVML: 33 against 15.**
- **cuBLAS: 169 against 19.** Since item 10 these include the f64 and complex level 1-3 surface (`D/C/Z gemm` in every batching form, `GemmEx` on R_64F/C_32F/C_64F, gemv, dot/dotc, nrm2, axpy, scal, trsm, trsv, trmm, trmv, syrk/herk, syr2k/her2k, symm/hemm, symv/hemv, ger, geam, dgmm, copy, swap, i?amax/i?amin, `getrfBatched`/`getrsBatched`, `geqrfBatched`/`gelsBatched`) and the host/device matrix and vector copies. That gives all 55 against 11 of torch's 55 cuBLAS imports, and all 90 cuBLAS names NVIDIA's `cusolver64_11.dll` imports.
- **Own NVRTC** (clang NVPTX) and **own cudart**. ZLUDA ships neither.

### Real PyTorch imports that neither project implements (measured, `--torch-gaps`)

- **cuBLAS (none; 39 before item 10).** The last 8, the batched QR and least-squares helpers `cublas{S,D,C,Z}geqrfBatched` and `cublas{S,D,C,Z}gelsBatched` (torch's batched `linalg.qr` and `lstsq`), are implemented since 2026-11-09 (`hw-logs/cublas-qr-perf-2026-11-09.md`).
- **cuSOLVER (97 of 97).** All `torch.linalg` decompositions.
- **cuSPARSE (62 of 98).** SpGEMM (sparse @ sparse), `csrgeam2` (sparse + sparse), SpSV/SpSM and `bsrsv2`/`bsrsm2` (triangular solves), `Xcsrsort`/`Xcoosort`, and the complex `C`/`Z` BSR products. We implement the other 36 (generic descriptors, SpMV, SpMM, SDDMM, S/D `bsrmv`/`bsrmm`, `Xcoo2csr`, legacy descriptors).
- **cuFFT: none since item 9.** torch 2.x plans FFTs through `cufftXtMakePlanMany` and `cufftXtExec`, which ZLUDA does not implement (both names are absent from its implemented list); we implement both.

Status of item 10 (branch `blas64`): done. `crates/cublas_shim` grows from 25 to 161 implemented names (all of ZLUDA's 19 but the constant `cublasGetCudartVersion`; 47 of torch's 55 imports, 16 before; the `--torch-gaps` "neither" list drops from 39 to 8).

Element precision is used for accumulation. op() is reduced to strides plus conjugate flags, so N/T/C/CONJG need no extra variants. Operand modes (triangular, symmetric, Hermitian), triangle-only stores and a C row stride make the same kernel serve trmm, symm/hemm, syrk/herk, syr2k/her2k, symv/hemv, ger and trmv.
