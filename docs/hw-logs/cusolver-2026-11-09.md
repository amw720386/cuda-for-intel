# cuSOLVER eigen and singular value routines on the Arc B390, 2026-11-09

Build: branch `cusolver-eigh` (`nvcuda.dll`, `cublas64_12.dll`, `cusparse64_12.dll`, `cufft64_11.dll`, `cfi_redirect.dll`, `cfi-run.exe`), release.
torch 2.2.2+cu118 under `cfi-run` with an untouched `torch\lib`, so NVIDIA's own `cusolver64_11.dll` runs and its kernels go through the translator.

## How the faults were found

1. `CFI_PTX_DUMP_DIR` and `CFI_DEBUG_COPYBACK=all` with `CFI_DEBUG_COPYBACK_DUMP` captured every module and the device memory before and after each launch of `torch.linalg.eigvalsh` (n = 32, float64).
   A host replay of each stage (numpy/scipy) showed that `sytrd4_cta` (tridiagonalisation) and the leaf `steqr_ker` solves were exact (1e-12 and 4e-16), but the divide-and-conquer merges (`laed2_par`, `laed3_epi1`, `laed3_epi2`) never wrote merged eigenvalues: `D` still held the leaf eigenvalues when they were rescaled and returned.
2. `CUDA_FOR_INTEL_TRACE=1` showed that the missing stage, `laed4_par` (the secular-equation solver), failed to translate with `barrier may execute divergently (branch on %p421 in block 84)`.
   `cuModuleGetFunction` returned `CUDA_ERROR_INVALID_PTX`, cuSOLVER ignored it, and the call reported success.
3. The 178 distinct PTX modules in `cusolver64_11.dll` (extracted from its fatbins) were probed with the corpus harness: 2695 of 2708 entries translated before the fix and 2699 after. The 4 recovered are the S/D `laed4_par` variants at 16 and 32 lanes.
   The remaining 9 are not used by torch: 8 `glu_csrilu0_*` (cuSolverSp spin loops with no path to a return) and `qr_colscale_setupG<qd_real>`.
4. The new `scripts/torch/solver_check.py` then hung the GPU (device lost, `CUDA_ERROR_LAUNCH_FAILED`) on float64 `eigvalsh` at n = 160.
   The trace ended at `sytrd4_gpu` (1808 blocks), which waits for other blocks' per-tile flags with `ld.volatile.global` in a loop and fences only after the loop.
5. Wide single-matrix `svd`/`svdvals` (25x40) failed with `CUSOLVER_STATUS_INTERNAL_ERROR` before any launch. The same call works on a Tesla T4 (Modal, same torch build).
   With a status trace added to the cuBLAS shim, the cause was `cublasDgeam` returning `CUBLAS_STATUS_INVALID_VALUE` for `beta = NULL, B = NULL`, which cuSOLVER passes to transpose the matrix.

## Fixes

- Translator, `flow.rs`: a `shfl.sync.idx` whose lane and control operands do not depend on the thread, and `vote` and `redux`, return a value that is the same in every lane. They no longer make a branch provably thread-divergent.
  `laed4_par` sums per-thread terms with `shfl.down`, broadcasts lane 0 with `shfl.idx`, and branches around `bar.sync` on the result. Regression tests: `flow_tests::shfl_idx_broadcast_branch_around_barrier_is_accepted_and_runs` (runs on the simulator) and `shfl_idx_from_thread_dependent_lane_is_rejected`.
- Translator, `normalize.rs`: `ld.volatile` and `ld.relaxed.{gpu,sys}` from global or generic memory are followed by a fence, as acquire loads already were. A plain SPIR-V load could be hoisted out of the spin loop or served from the non-coherent L1.
  Shared, local, param and const loads and all stores are unchanged. Regression test: `tier2_tests::volatile_and_relaxed_device_global_loads_are_fenced`. `TRANSLATOR_VERSION` is now 7.
- cuBLAS shim: `?geam` treats a null `beta` with a null `B` as beta = 0, and does not validate `ldb` when `B` is null. Regression test: the null-B transpose case in `cublas64_tests`. `CFI_CUBLAS_TRACE` now also logs the expression that produced a failing status.
- Driver: `cuMemcpy` and `cuMemcpyAsync` resolve through `cuGetProcAddress` from ABI 4000 (CUDA 4.0), not 7000, so cudart 11.8's `cudaMemcpyDefault` path finds them.
  A kernel that fails lazy translation is now reported once on stderr, because libraries such as cuSOLVER continue without it.

## Results

`cfi-run.exe --install-dir <bin> -- python scripts/torch/solver_check.py`: **279 checks passed, 0 failed** (13 s), plus 1 recorded gap (below).
Tolerances are relative to max(1, max |CPU|): 2e-3 (float32, complex64) and 1e-9 (float64, complex128) for most values, residuals and orthonormality. The clustered-eigenvector check allows 10 times that, and pinv 100 times.

Covered for float32, float64, complex64 and complex128:
- `eigvalsh` and `eigh` (residual and orthonormality) at n = 1, 5, 8, 17, 32, 33, 64, 100, 160, batched (4)x16, (3)x32, (2)x40 and (2,3)x9, both `UPLO`, clustered and repeated eigenvalues, and a diagonal input.
- `svdvals` and `svd` (reduced and full; reconstruction and orthonormality) at 1x1, 8x8, 32x32, 40x25, 25x40, 64x64, 100x37, 130x130, batched (4)x16x16, (3)x32x20, (2)x20x32 and (2)x48x48.
- `pinv`, `pinv(hermitian=True)` and `matrix_rank` (also batched) on rank-deficient inputs.
- `eigh` backward (float64) and `svdvals` backward (float64, complex128).

`scripts/torch/blas64_check.py`: **527 checks passed, 0 failed**. Its informational section now reports `linalg.eigh` and `linalg.svd` as "ran, matches CPU" next to solve, inv, det, cholesky, qr and lstsq.
GPU tests `hw_cublas64` (2) and `hw_cublas_batched` (3) pass.

Before these fixes, `eigvalsh` (n = 32) had relative error 0.74, and float64 n = 160 hung the GPU.
With only the `laed4_par` fix, `svdvals` 32x32 (`gesvdjBatched`) already matched in a fresh process, so the earlier `CUSOLVER_STATUS_EXECUTION_FAILED` in `blas64_check.py` probably came from the failed eigh before it. This was not re-run on the old build.

Of the 582 corpus files, only `handwritten/memory/ld_volatile_global.ptx` and `handwritten/barrier/ld_relaxed_sys.ptx` translate differently. No ggml kernel changes.

Offline (macOS): 284 lib and simulator tests pass, plus 76 `cublas_shim` tests. The corpus matches `expected_status.tsv` (pass 555, unsupported 57, error 15). The ZLUDA vectors give 179 pass and 7 expected failures out of 186.

Still failing:
- complex128 `eigh` backward: torch 2.2.2+cu118 ships one kernel it needs as an `sm_37` cubin with no PTX (`CUDA_ERROR_NO_BINARY_FOR_GPU`). This is a gap in the torch build, not in cuSOLVER. `solver_check.py` records it as `GAP`.
- batched `linalg.qr` still needs `cublas?geqrfBatched`.
