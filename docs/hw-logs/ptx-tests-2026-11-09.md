# vosen/ptx_tests on the simulator and the Arc B390 (2026-11-09)

Roadmap item 1 of `docs/zluda-parity.md`. ZLUDA's per-instruction suite (vosen/ptx_tests 76d4dce, MIT OR Apache-2.0)
runs unmodified apart from `tests/ptx_tests/ptx_tests.patch` (input sampling through `PTX_TESTS_ELEMENTS`, one failed
Driver API call fails one test instead of the process, `[workspace]` so it builds inside our tree).

- **Simulator (macOS):** `sh tests/ptx_tests/run.sh [--exact-ftz]`. ptx_tests loads `simcuda`
  (`tests/ptx_tests/simcuda`), 12 Driver API calls over `src/ptx.rs` (the translator `nvcuda.dll` uses) and
  `src/ptx/sim.rs`. 65536 inputs per case; 20 s on 10 cores. CI job `ptx-tests-sim`.
- **GPU (B390, driver 32.0.101.9033):** `scripts/hwvalidate/ptx_tests.ps1 -Nvcuda <nvcuda.dll>`, our `nvcuda.dll`
  with `CFI_NO_CACHE=1`, 4194304 inputs per case (range tests: the lowest and highest 524288 values, then uniform
  random), 6 processes, 12 s per mode inside one GPU-queue slot. Windows lists 787 cases: the 6 directed `sqrt` cases
  need `rug`, which ptx_tests skips on Windows.

Every case either passes or is listed in `tests/ptx_tests/expected_status.tsv` with its reason; both runs match it.

## Result

Before this work no case loaded: every ptx_tests kernel names registers without `%` (`.reg .u64 input_addr;`), which
is valid PTX the parser rejected. With only that fixed, 548 of 793 passed on the simulator (136 unsupported, 81 wrong,
28 stopped the simulator).

## What still differs, and why

| Cases | Mode | Reason |
| --- | --- | --- |
| `bfe_rng_u64`, `bfe_rng_s64`, `bfi_rng_b64` | both | PTX ISA: only bits 0-7 of `pos` and `len` count. NVIDIA hardware uses all 32 bits for 64-bit operands (marked ERRATA in ptx_tests itself). We follow the ISA. First failing input: `bfe.u64` of 0xE4FB572AC44FF750, pos 303, len 291: we return 0x1C9F6 (pos 47, len 35), hardware 0 |
| `cvt_invalid` | both | `cvt.f16.s16` without a rounding modifier is invalid PTX that ptxas rejects; we accept it (round to nearest) |
| `cvt_rm_ftz_f16_f32`, `cvt_rp_ftz_f16_f32`, `cvt_rp_ftz_sat_f16_f32` | exact-ftz | PTX ISA: `.ftz` flushes subnormal f32 sources. Hardware does so for `.f16.f32` only with integer rounding (ERRATA in ptx_tests). With `CFI_EXACT_FTZ=1` we follow the ISA; by default (`.ftz` ignored) these pass |
| 115 `*_ftz*` cases (119 on the B390 sample) | default | `.ftz` is ignored by default (`docs/translator-coverage.md`): results differ only for subnormal inputs or results. Every one has a passing non-`.ftz` sibling and passes with `CFI_EXACT_FTZ=1` |

## Fixes (regression tests in `src/ptx/ptx_tests_regressions.rs`): 12 translator bugs (1-12), one feature (13), one simulator gap (14)

1. Bare register names (`.reg .u64 in_addr;`) were rejected; declared names now get the `%` prefix before parsing.
   34 more corpus files now pass without the harness's own renaming.
2. `cvt.sat.{u32,u64}.{s8,s16}` dropped the clamp of negative values to 0.
3. `cvt.{rni,rzi,rmi,rpi}[.sat].{f16,f32,f64}.<float>` ignored the integer rounding (`cvt.rni.f16.f16` was a copy).
4. `testp.normal` was false for +-0; NVIDIA reports zero as normal.
5. `cvt.u64.s32` and `cvt.s64.u32` were unsupported.
6. `cvt.rn.ftz.f32.{s16,s32,u32}` were unsupported.
7. `set.CMP.{and,or,xor}[.ftz].{f32,u32,s32}.f32` (84 cases) and float `setp` with a combine were unsupported.
8. `{add,sub,mul,fma}.{rz,rm,rp}[.ftz].sat.f32` were unsupported (directed operation, then the [0, 1] clamp).
9. `{div,sqrt,rcp}.{rz,rm,rp}.f32` were unsupported; now through f64 (the f64 quotient or root rounded to nearest is
   never an f32 value unless the exact result is, so narrowing it with the directed mode is exact).
10. `mad.hi.{u16,s16}`, `sad.{u16,s16}` and `mad.hi.sat.s32` were unsupported.
11. `div.approx.f32` returned a tiny quotient for 2^126 < |b|; PTX returns 0 (NaN for infinite a). `div.full.f32`
    no longer shares that path.
12. Found on the B390 only (4M samples): `sub.rm.f32 +0, +0` and `add.rm.f32 +0, -0` returned +0; IEEE 754 gives -0
    for every exact zero sum under round-down except +0 + +0.
13. Opt-in exact `.ftz` (`CFI_EXACT_FTZ=1`): subnormal f32 sources and results, and f16/f16x2 lanes of the half
    forms, become signed zeros. Five integer operations per operand, so it is off by default.
14. Simulator only: directed conversions to f16 (`cvt.rm.f16.f32`) stopped the simulator; it now models RTN and RTP.

Also from the 7 ZLUDA execution vectors that failed: adding two global addresses (`stateful_neg_offset`) now yields a
plain integer, so 180 of 186 vectors match. The 6 left are listed in `src/ptx/zluda_vector_tests.rs`.

`TRANSLATOR_VERSION` is 7.
