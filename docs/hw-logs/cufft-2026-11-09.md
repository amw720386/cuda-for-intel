The redirect log shows `torch\lib\cufft64_10.dll` requested by full path and served by `<install>\aliases\cufft64_10.dll` (our `cufft64_11.dll`).
The first run had an abort at interpreter exit: torch's plan cache calls `cufftDestroy` from an exit handler and the driver cannot be entered then.
`cufftDestroy` now skips device frees while the process is shutting down (`RtlDllShutdownInProgress`); the rerun exits cleanly.
