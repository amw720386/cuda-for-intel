# Running stock PyTorch on the shim (Windows, Intel Arc)

Tested on an Arc B390 with `nvcuda.dll` from this repo standing in for the NVIDIA driver.
Branch `hw-torch`. Everything below was measured on hardware against CPU results.

## Which PyTorch builds work

PyTorch's own wheels only help if the CUDA fatbins contain PTX, because the shim translates
PTX (never SASS). Verified by scanning the wheels' `.nv_fatb`:

| build | PTX | status |
|---|---|---|
| Windows wheel `torch 2.2.2+cu118` (download.pytorch.org/whl/cu118) | compute_37, ISA 7.8 | works (details below) |
| conda-forge `pytorch 2.13.0 cuda128` (micromamba, `CONDA_OVERRIDE_CUDA=12.8`) | compute_120, ISA 8.7 | works: matmul, Linear, softmax, layer_norm, gelu, sum, conv2d fwd/bwd, SDPA math, randn, autocast fp16, SGD training loop |
| Windows wheels cu121 to cu130 (2.1 to 2.9) | none (SASS only) | cannot run |
| Linux cu129/cu130 wheels | compute_120 | not tried (Windows host) |

## Staging on the box

1. Create a venv (cu118) or a micromamba env (cuda128) in your own directory. Install nothing
   into system locations.
2. Put the shim's `nvcuda.dll` in a private directory and `ctypes.WinDLL()` it **before**
   `import torch` (a loaded module named `nvcuda.dll` satisfies later by-name loads).
3. Replace the CUDA math libraries in torch's DLL directory (keep `*.orig` copies):
   `cublas64_11.dll` + `cublasLt64_11.dll` (cu118) or `cublas64_12.dll` + `cublasLt64_12.dll`
   (cu12) with the built `cublas64_12.dll` of this repo (one DLL exports both the cublas and
   cublasLt names). Windows resolves all imports at load; names the shim does not implement
   are exported as NOT_SUPPORTED stubs generated by `scripts/torch/gen_cublas_stubs.py` from the
   wheel DLLs' export lists (`pefile`).
4. Set `CUDA_FOR_INTEL_HYBRID_DIR` to a directory containing the signed
   `nvcudart_hybrid64.dll` (SHA-256 `BF430D65B863C49BAB525001A0712992D17F52F4B5A205536160A337CF8B22B3`,
   see docs/agent-handoff.md). Set `CUDA_MODULE_LOADING=LAZY`, and
   `torch.backends.cudnn.enabled=False` (no cuDNN backend; conv uses ATen's native kernels).
5. Never commit third-party binaries or generated PTX.

## Environment variables

| variable | effect |
|---|---|
| `CUDA_FOR_INTEL_TRACE=1` | trace driver entry points to stderr; `CUDA_FOR_INTEL_TRACE_ENTER=1` also logs entries; access violations in loaded modules are logged with module+offset |
| `CFI_PTX_DUMP_DIR=dir` | write `raw_<hash>.ptx` (module PTX as supplied), `module_<handle>.ptx` (prepared), failing PTX, and per-kernel `.spv` |
| `CFI_REPORT_CC=major.minor` | compute capability reported to applications. Default: chosen from the loaded torch build (`torch_cuda.dll` + `cudart64_110.dll` -> 3.7, + `cudart64_12.dll` -> 12.0), 7.5 for every other process. Explicit value always wins; see docs/torch-arch-guard-stubs.md |
| `CFI_XMX=0/1/2` | native XMX (DPAS) fp16/bf16 GEMM: unset or 1 = on for qualifying calls (min(m,n) >= 128 and m*n*k >= 2^24; `CFI_XMX_MIN_DIM`, `CFI_XMX_MIN_WORK`), 0 = off, 2 = force for every qualifying call |
| `CFI_ALLOW_EMPTY_KERNELS=1` | load architecture-guard stub kernels instead of failing with CUDA_ERROR_NO_BINARY_FOR_GPU (209) |
| `CFI_NO_ALLOC_TOUCH=1` | skip the zero-fill of fresh `cuMemAlloc` buffers (without it a kernel's first touch of an untouched Level Zero allocation loses the device) |
| `CFI_CUBLAS_TRACE=1` | trace cublasLt plan failures |
| `CFI_NO_CACHE=1`, `CFI_CACHE_DIR` | disable / relocate the on-disk translation cache (`src/cuda/xcache.rs`, keyed by PTX hash + entry + translator version + `CFI_*` switches) |

## Tools

`tests/ptx_corpus/harness`: `ptx-corpus-harness --probe module.ptx` translates every `.entry` of a
module on its own and groups the failures; `--prep` prints the normalised PTX. It builds on
macOS (it includes `src/ptx` directly).

## What works (cu118, compared with CPU)

zeros, add, matmul all transposes, bmm, Linear fwd/bwd, relu/gelu/softmax/layer_norm/sum,
conv2d fwd/bwd, max_pool, embedding, index_select, cat, fp16 cast and autocast matmul,
rand/randn/dropout (ATen Philox; no curand shim needed), batch_norm, SGD and Adam (foreach
included), AdamW, TransformerEncoderLayer fwd and all gradients, Events, Streams, pinned
non-blocking copies, memory_stats.

## Known gaps

- Memory-efficient SDPA on cu118: the compute_37 PTX of `fmha_cutlassF_*` is an architecture-guard
  stub. With the default cc the shim now fails loudly (209); use `CFI_REPORT_CC=3.7` or disable
  the mem-efficient/flash SDP backends.
- Translator: 2 `complex<double>` foreach kernels (multi-depot `.local` inlining); some ATen
  modules (cuda128: 61 of 308) are too large to probe in 15 minutes per module, and about 6% of
  entries in the probed cuda128 modules still fail (`mov.s32`/`cvt.s8.s32` forms, `atom.add.noftz.f16/bf16`,
  `vote.ballot.sync`, `lg2.approx.f32.ftz`, `ldmatrix`, divergent-barrier rule, "too many PTX blocks"). 8% of
  cuda128 entries are architecture-guard stubs.
- cuDNN/NCCL/cuFFT/cuSOLVER paths are not available; first use of a very large module takes tens of
  seconds (see the translation cache).
- Shutdown logs `cuLibraryUnload 999` after Level Zero teardown (harmless).

## Expected speeds (Arc B390, torch 2.13 cuda128 and 2.2.2 cu118)

| operation | XMX off | XMX on (default) |
|---|---|---|
| fp16 matmul 2048^3 | 14.7 ms (1170 GFLOP/s) | 4.8 ms (3560 GFLOP/s) |
| fp16 Linear fwd+bwd, batch 64, hidden 1024 | 1.7-2.0 ms | 1.4-1.5 ms |

The first use of a large ATen module translates its kernels (a cold GPT-style 4-layer
encoder forward+backward took about 210 s); the on-disk translation cache makes warm runs
about 16 s. Use `CFI_NO_CACHE=1` to disable the cache.

## Smoke tests that pass (cuda128, auto cc 12.0, cudnn off, equal to CPU at the same seed)

* 4-layer causal TransformerEncoder (d=64, 4 heads): forward rel err 2.4e-07, all 48 grads <= 5.2e-07.
* ResNet-18 on random 32x32 images: loss identical (2.35571); fc grad rel err 3.3e-06.
* MLP, 50 Adam steps (foreach): worst relative loss difference 5e-07.
* Linear/transformer sets with XMX on and off give identical results.

## Translator status on the cuda128 build (probe of all 308 sm_120 PTX modules)

19480 of 19529 entries (99.7%) translate. Known remaining gaps:

* 36 entries still rejected by the divergent-barrier rule (the rule cannot prove block
  uniformity for these tid-dependent conditions; `CFI_STRICT_BARRIERS=1` makes it stricter).
* Huge kernels no longer hit the old 8192-block limit: the flow analysis is linear now (no
  per-block register sets, post-dominator tree instead of an N x N matrix), and the limit is
  1M blocks.
* 2 entries with a missing register declaration, 2 entries beyond the register-range limit.
* 48 modules contain only device functions (no `.entry`) and need no translation.
